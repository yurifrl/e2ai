# Phase 1 Plan: Web happy path — deterministic foundation

**Goal:** The full report-only QA loop for bet-app web on every deploy: webhook → run → deterministic Playwright suite → verdicts → live HTML report + sticky PR comment.

**Requirements covered:** INTG-01..03, APPS-01..02, INGE-01..03, SUIT-01..02, VERD-01, REPT-01..03, SECR-01, PLAT-01 (16/45)

**Research:** `RESEARCH.md` (703 lines, HIGH confidence) — all patterns, DDL, and pins below come from it.

## Locked decisions

- Stack: Go 1.26.6 hexagonal (`api/`), Connect-RPC via admin-bff, Postgres 16 + River (`riverqueue/river` + `riverpgxv5`), Bun+Vite web module (port 3005), Tilt dev stack (`allow_k8s_contexts(["orbstack"])`), 1Password `.env.op` secrets.
- Suite = existing MSW-mocked bet-client Playwright specs, executed **locally at `head_sha`** (Pattern 4); staging rollout gate decides **when** (health_url poll), never alters the suite.
- Verdicts: evidence-anchored only, precedence INFRA_ERROR > FAIL > FLAKY > PASS > INCONCLUSIVE; never exit codes.
- GitHub: sticky comment via marker `<!-- e2ai:run:{slug} -->` find-then-update; check-run always `conclusion: neutral`; PR resolved by head SHA (`workflow_run.pull_requests` is empty for dispatch runs).
- Queue isolation: api container = `default` queue only; runner container = `runner` queue only, MaxWorkers 1. Execute job River timeout 60m.
- Ports: api 8082, postgres 5434, web 3005. BFF stanza: prefix `/e2ai` → localhost:8082.
- No agents (P3), no mobile (P4), no plans/approvals (P2), no flake governance (P5).

## Wave 1 — schema + registry + verdict core

### T3: Postgres migrations + app registry seeding
- **Files:** `api/internal/app/{postgres.go,service.go,migrations/0001_init.sql}`, extensions to platform config for registry loading.
- **Steps:** DDL exactly per RESEARCH.md § Postgres schema: `registered_apps`, `webhook_events` (unique app+delivery), `runs` (unique app+workflow_run_id, summary/verdict columns, error_note), `test_results` (outcome/status/attempts/attachments), `artifacts`, `pr_comments` (unique app+pr). ### T4: Verdict engine (pure)
- **Files:** `api/internal/verdict/{verdict.go,classify.go,verdict_test.go,classify_test.go}`.
- **Steps:** Table-driven mapping over parsed test rows (outcome/status enums from T2 fixture — not assumed values): expected→PASS, flaky→FLAKY, unexpected+failed/timedOut→FAIL, interrupted/missing→INFRA_ERROR, skipped→INCONCLUSIVE. Run-level precedence: no parseable results → INFRA_ERROR (error_note names the stage) > any FAIL > any FLAKY > all-PASS > no-tests/all-skipped → INCONCLUSIVE. Failure classification heuristics: infra (clone/build/serve/timeout), test_gap (assertion failure with clean MSW interaction), app_bug (deterministic UI failure vs fixture). `agent_flake` rule exists but cannot fire in P1.
- **Acceptance:** `go test ./internal/verdict/ -count=1` covers every precedence rule including no-results and zero-tests cases; table rows cite the T2 fixture's real enum values.
- **Reqs:** VERD-01, REPT-02, SUIT-02.

## Wave 2 — ingest + runs + GitHub client

### T5: Webhook ingest + reconciliation sweep
- **Files:** `api/internal/ingest/{http.go,dedupe.go,sweep.go,ingest_test.go}`, connect handler registration in `cmd/e2ai-api`.
- **Steps:** `POST /github/webhook/` (BFF forwards): read raw body → HMAC-SHA256 verify (`hmac` + `subtle.ConstantTimeCompare`) → match registered app (workflow name + display_title_pattern) → filter (event=workflow_dispatch, conclusion=success) → in ONE tx: insert `webhook_events` (ON CONFLICT app+delivery → 202 already-known), insert `runs` (ON CONFLICT app+workflow_run_id → 202), `river.InsertTx(WaitRolloutArgs)` with UniqueOpts across available/running/pending → return 202 immediately. Reconciliation sweep: River periodic job `e2ai:ingest:reconcile` every ≥5 min listing recent completed dispatch runs per registered workflow (`GET /actions/runs?workflow_id&event=workflow_dispatch&created=>since`), ingesting missing run_ids through the same tx path. Fake-GitHub httptest server for tests.
- **Acceptance:** `go test ./internal/ingest/ -count=1`: bad signature → 403 + no rows; valid → 202 + run row + job enqueued atomically (assert all three in the same committed tx); duplicate delivery GUID → 202, single run row; sweep picks up a synthetic missed run and stays idempotent on second pass.
- **Reqs:** INGE-01, INGE-02.

### T6: Runs domain + GitHub REST client

## Wave 3 — pipeline jobs (queue wrappers)

### T7: `e2ai:run:wait-rollout` rollout gate job
- **Files:** `api/internal/ingest/rollout.go` (+ tests).
- **Steps:** Poll `health_url` from registry (2s interval, 15m budget; deadline-driven, MaxAttempts 1). Healthy → transition run to `provisioning`, enqueue execute. Timeout → transition run `failed`, verdict INFRA_ERROR, error_note "rollout gate timeout". `health_url` null → fixed 5m wait fallback (house Checkly precedent preserved).
- **Acceptance:** `go test ./internal/ingest/ -run TestRollout -count=1`: healthy URL → execute enqueued; always-500 URL with 15m budget shortened in tests → INFRA_ERROR path.
- **Reqs:** INGE-03.

### T8: `e2ai:run:execute` job + Playwright runner container
- **Files:** `api/internal/suite/{execute.go,parse.go,parse_test.go}`, `runner/Dockerfile`, `runner/entrypoint notes`, `cmd/e2ai-runner` completion.
- **Steps:** Runner image: `mcr.microsoft.com/playwright` base pinned to bet-client's `@playwright/test` version (verify at scaffold; corepack + yarn from committed lockfile). Execute: transition run to `executing` → create check-run `in_progress` on head_sha → clone bet-app at head_sha (shallow) → `yarn install` (frozen lockfile) + `yarn build:e2e` → write `.env.e2e` from registry + 1Password-injected values (nothing plaintext in repo) → `CI=true yarn start:e2e` background → `npx playwright test --reporter=blob,json` (PLAYWRIGHT_JSON_OUTPUT_NAME=results.json) → `merge-reports --reporter html` → parse results.json (fixture-grounded T2 parser) → insert test_results rows (with per-test attachments: screenshots/traces relative paths) + artifacts rows (html_report, blob, results_json, logs) → transition `reporting`, enqueue report. River: queue `runner`, MaxWorkers 1, Timeout 60m, MaxAttempts 2 (retry only when artifacts absent/corrupt ⇒ runner crash; never re-run after verdicts recorded). Runner container registers ONLY the `runner` queue.
- **Acceptance:** `go test ./internal/suite/ -run TestParse -count=1` parses the real T2 fixture (all 4 outcomes → correct rows); retry-guard unit test: attempt 2 with existing verdicts is a no-op. Full container execution verified in T13.
- **Reqs:** SUIT-01, PLAT-01, VERD-01 evidence capture, SECR-01 (runner env assembly).

### T9: `e2ai:run:report` job skeleton
- **Files:** `api/internal/report/{job.go}`, wire in cmd/e2ai-api.
- **Steps:** Queue `default`, MaxAttempts 3 (GitHub 5xx/backoff). Payload: load run + test_results + summary → invoke verdict engine → persist verdict + summary counts + duration → transition `completed` (or `failed` on internal error) → hand off to comment/check/report-data assembly (T10) — job wrapper and transactional state transition live here, payload assembly in T10.
- **Acceptance:** `go test ./internal/report/ -run TestJob -count=1`: verdict persisted, transition recorded; failed verdict-derivation → run `failed` with error_note (never silent).
- **Reqs:** VERD-01, SUIT-02.

## Wave 4 — report worker payload

### T10: Sticky comment + neutral check-run + report link
- **Files:** `api/internal/report/{comment.go,check.go,comment_test.go}`.
- **Steps:** Resolve PR by head SHA (`/commits/{sha}/pulls`; empty → skip comment, log). Find comment by marker `<!-- e2ai:run:bet-app-web -->` in PR comments → PATCH, else POST (upsert `pr_comments`). Body: verdict header, counts, duration, report-page link (signed HMAC link w/ run id — works outside shell auth), top failures w/ embedded artifact `<img>` URLs (path-sanitized), escaped titles/error text (no HTML injection). Check-run: PATCH `status: completed, conclusion: neutral, output: {title, summary, details_url}`. Rate-limit-aware, one update per run.
- **Acceptance:** `go test ./internal/report/ -count=1` against fake GitHub: no PR → no comment; PR → create once, second run PATCHes the same comment (count stays 1); conclusion always `neutral` (never success/failure); injected `<script>` in a test title renders escaped in the comment body.
- **Reqs:** REPT-03, SECR-01, VERD-01 (report-only contract).

### Success Criteria:
- Full autonomous loop demonstrable end-to-end (T13): webhook 202 → run transitions → verdict → report page → sticky comment + neutral check-run, retriable at every stage via River.
- Every verdict traceable to evidence rows (screenshots/traces/results.json), never exit codes (VERD-01).
- Rollout gate uses health polling, not blind sleep (INGE-03); suite runs at head_sha with bet-client's own config/projects (SUIT-01, PLAT-01).
- Secrets only via `op://` refs; redaction verified; artifact serving traversal-safe (SECR-01).
- `go test ./...` green; web manifest schema-valid; admin-bff stanza wired (INTG-01..03).
