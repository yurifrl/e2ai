## Typography

Font stack: Inter (`--font-sans`), JetBrains Mono (`--font-mono`). Ramp: exactly four sizes and two weights — 400 for body, 600 for everything emphasized (chips, labels, buttons, titles, KPI numerals). This amends the locked sketch with two one-line deltas, same mechanism as the 4→5 KPI-card amendment: display numerals drop 26px→28px (single display size) and 700→600 (weight consolidation).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 | 1.5 | Form inputs, panel body copy, confirm block lines |
| Dense body | 14px | 400 | 1.5 | Feed detail/agent lines, rail secondary text, runlines |
| Label / chip / mono metadata | 12px | 600 | 1.2 | Status + verdict chips, KPI labels (uppercase, letter-spacing 0.07em), timestamps, SHAs, ids, KPI `small` suffix (%, units; folded from 13px) — mono for machine values (`--font-mono`) |
| Display + page title | 28px | 600 | 1.2, letter-spacing −0.5px (numerals only) | KPI numerals (sketch `.kpi .val`, amended 26px→28px) and pagehead h1 (`--text-2xl`) |

Buttons render at 14px/600; the primary armed confirm button inherits house primary styling. Rail-card titles are 14px/600 (sketch `.railcard h3`, weight amended) with a bottom border separator.

Production reconciliation: shipped house chips (`web/src/features/runs/chips.tsx`) render 12px/`font-medium` (500); cockpit chip instances use `font-semibold` (600) per this contract — the 500→600 delta is absorbed by this amendment, house chip migration stays out of phase scope.

## Color

Theme tokens live in `.planning/sketches/themes/default.css` — the Tailwind preset supplies the same palette names (`bg-muted`, `text-muted-foreground`, `blue-100/800` etc. as used by house chips).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg: hsl(220 20% 97%)` | Page background |
| Secondary (30%) | `--surface: hsl(0 0% 100%)` (+ `--surface-2/3` for hover/dividers) | Cards, rail, feed rows, panels |
| Accent (10%) | `--primary: hsl(214 100% 50%)` (halo `--primary-soft`) | Reserved list below |
| Destructive | `--danger` (theme token) | Pause-arm confirm button, paused banner border, stuck-session dot, ceiling-0 rejection notice |

Accent reserved for: the "Trigger run" primary button and its armed "Confirm trigger" step-2 state; the active app-filter chip; the LIVE chip dot + pulse (running rows in the feed); created-run and report links; focus rings; the new-row slide-in highlight (`--primary-soft`). Never used for plain text, tables, or borders elsewhere.

Semantic tones (fixed taxonomy, from house chips): success/`--success` = PASS + `watch` agent dot + accepted ingest; warning/`--warning` = FLAKY + budget ≥80% + paused banner; danger = FAIL + stuck sessions + exhausted budget. Feed chips reuse `StatusChip`/`VerdictChip` colors exactly; the LIVE chip is `blue-100/blue-800` with a pulsing `--primary` dot (sketch `.chip.live`).

Agent-tag colors are per-role theme tokens (sketch `.agent-tag.navigator/.judge/.analyst`): Navigator/Vision Judge/Flakiness Analyst keep their fixed tints.

| Pagehead subline | "The QA arm, always reporting. Never blocking." (sketch verbatim) |
| Empty state — feed | Heading "No runs yet"; body "Runs appear here the moment the arm starts reporting — trigger one manually or wait for the next deploy." + secondary button "Trigger run" |
| Empty state — agent rail | "No live agent sessions" body "Sessions appear here the moment a run starts working." |
| Empty state — simulate | "Pick an app and a payload shape, then fire a signed webhook at the real ingest seam." |
| Empty state — filtered feed | "No runs for {app} yet — clear the filter or trigger one." |
| Error state — polling failure | "Couldn't refresh {surface} — showing the last known state. Retrying on the next tick." (inline `Alert`, warning tone; payload retained per `usePolling`) |
| Error state — trigger 409 | "A run for {app} just started — the feed will show it shortly. Only one trigger can claim {app} at a time." |
| Error state — paused blocks action | "The arm is paused — {reason}. New triggers and simulated webhooks are blocked until resume." |
| Error state — budget exhausted | "Daily cap reached for {app}: {spend} of {cap} used. Raise the cap or wait for the UTC reset." |
| Error state — ceiling 0 | "This plan has a zero budget ceiling and cannot be triggered. Set a positive ceiling first." |
| Escape hatch — zero approved | "No approved plan versions for {app}. Open Approvals to review pending plans." + button "Open Approvals" |
| Draft picker row | "Draft — pending approval" (row disabled with this one-line reason) |
| Destructive confirmation | **Pause arm**: step 1 "Pause arm" (warning-tone button) → step 2 requires a reason input and confirms "Confirm pause — triggers and simulates are blocked until you resume." Resume is a single click (no confirm) labeled "Resume arm" |
| Re-run actions | "Re-run same commit (reproduce)" / "Re-run latest head (retest)" with subline "Creates a new run — the original run is never modified." |
| Confirm block lines | "Plan: {plan name} v{n} (approved · hash pinned)" · "Run shape: {n} steps · {targets} · ceiling {cap}" · "Budget: {spend} of {cap} used today — {remaining} remaining" or "Budget: no cap set for {app} — this run proceeds uncapped" |

Destructive actions in this phase: global pause only. Trigger/simulate actuate the arm, not the app under test — never framed as destructive; their gate is the budget/pause state, not a confirm-by-default.

## Screen Contracts

### A. Command Center — module root landing (`/e2ai`, route index)

Sketch 001-A anatomy, in order:

1. **Pagehead** — h1 "Command Center" + subline (sketch verbatim); right cluster: primary **Trigger run** button (opens panel B) + app-filter chip row ("All apps" + one chip per registered app; active chip uses accent, inactive `--surface-2`). The sketch's "+ Simulate tick" harness button is a sketch-only artifact — excluded.
2. **KPI header** — 5 cards, `grid-template-columns: repeat(5, 1fr)` (sketch shows 4; roadmap replaces "Flaky suspects" with the budget + arm-state cards it mandates):
   - **Runs today** — numeral + muted "vs yesterday" delta line.
   - **Pass rate** — numeral with `%` small + delta points.
   - **Pending approvals** — numeral + delta line; whole card is a link to `/e2ai/approvals`; warning tone when > 0.
   - **Budget spend vs cap** — mono `{spend} / {cap}` + sub-line naming the highest-utilization app ("bet-client 82% of cap"); warning tone ≥80%, danger when any app is exhausted; uncapped apps render the explicit "no cap" state — never a refusal or blank.
   - **Arm state** — Badge "LIVE" (success) or "PAUSED" (warning) + pause control: two-step arm-confirm ("Pause arm" → reason input → "Confirm pause"). While paused, a full-width warning banner sits above the KPIs: "The arm is paused — {reason}." + attribution "Paused by {operator} · {timestamp}" + "Resume arm" button. Pause state is visible at all times (COCK-04) — never hidden behind a menu.
3. **Feed (left, `1fr`)** — reverse-chronological rows per sketch anatomy: mono time (`when`) · status/verdict chip + LIVE chip for in-flight runs · `{app} · #{run id}` mono · plan + targets (`plan`) · evidence thumbnails (`62×42`) when present · chevron. Rows with a detail strip expand inline on click (house toggle, `aria-expanded`): verdict, duration, cost (mono), evidence links, then agent/triage lines (session failures, quarantine proposals, triage arrivals as feed events per COCK-02). New rows animate in with the sketch `slidein` keyframe + `--primary-soft` background, respecting reduced motion (below).
4. **Right rail (320px)** — stacked cards:
   - **The Arm — agents online** (COCK-03): one row per live session — status dot (busy = primary pulse / watch = success / idle = gray / stuck = danger with static red dot + "Stuck" label when heartbeat lapse > 90s, API-computed), role name + one-line activity, right-aligned mono context. Stuck rows link to Run Detail.
   - **Latest reports** — last few runlines: verdict chip + mono `plan · #{id}` link to Run Detail.
   - **Webhook simulate** (screen D).
5. **Polling** — `usePolling` while visible: feed + KPIs 10s; agent rail 5s. First paint: `Skeleton` KPI cards + `LoadingState` feed. Polling error: warning `Alert` + retain last payload. App filter chips constrain the feed client-side against the polled page (sketch behavior).

Navigation: `web/admin.module.json` gains a first `commands[]` entry `command-center` (route `/e2ai`, icon `activity`, section `operations`) and `routes.tsx` index route renders `CommandCenterPage`. Page visibility is permission-aware per manifest `permissions`; mutation controls (trigger/simulate/pause) render **disabled with tooltip "Requires admin.e2ai.edit"** when the viewer lacks the permission — hidden-never, per audit visibility.

### B. Trigger panel (TRIG-01..05) — inline expanding panel under the pagehead

One house-built component mounted three ways this phase: cockpit pagehead (primary), `PlanDetailPage` ("Trigger run" with version preselected), `RunDetailPage` re-run pair. Registry-card mount is deferred to Phase 9 (CONTEXT boundary). No modal: the panel is a `Card` that expands below the pagehead; opening it pauses nothing — the feed keeps polling behind it.

**Step 1 — pick (form):**
- App `Select` → Plan version `Select`: approved versions only. Disabled draft rows render with the "Draft — pending approval" reason; a zero-approved app collapses the picker into the escape-hatch `Alert` (copy above). One version preselected when exactly one is approved.
- Head source: radio pair — "Latest default-branch head" (default) / "Pin commit" with mono SHA `Input` prefilled with the current default-branch head; "Reproduce" from Run Detail preselects pin with the original run's SHA; "Retest" selects latest head (TRIG-04 semantics, append-only).
- Reason `Textarea` — one line, 200-char cap, optional, placeholder "Reason (optional) — e.g. reproducing #4812".
- **Pre-flight budget strip** (always visible, live): mono `{spend} of {cap} today · {remaining} remaining` for the chosen app, or "No cap set — this run proceeds uncapped" (explicit state, never a refusal). Warning tone ≥80%, danger + step-2 disabled when exhausted. Adjacent paused warning when the arm is paused.

**Step 2 — armed confirm (TRIG-03):** a bordered confirm block restating: resolved plan identity (name, approved version, source PR/SHA, "hash pinned" mono badge), run shape (step count, targets, `trigger_source='manual'`, "bypasses wait-rollout"), budget line (copy above). The armed **Confirm trigger** button submits; a 202 turns the panel into a success line linking the created run in the feed; a 409 renders the inline 409 copy and the panel stays open.

**Disabled-with-reason matrix (never silently queued):** paused arm, budget exhausted, zero approved versions, ceiling-0 plan — each disables step 2 and renders its exact error-state copy adjacent to the button. Two concurrent triggers serialize server-side to exactly one 202 + one 409; the loser sees the 409 copy inline.

### C. Run Detail additions (TRIG-04, AUDT-01)

- Attribution line under the run header: "Triggered by {operator} · {timestamp} · manual" (deploy runs keep their existing header; manual runs show the line).
- Re-run control block: the two arm-confirm buttons "Re-run same commit (reproduce)" / "Re-run latest head (retest)", each opening the shared trigger panel prefilled per the head-source mapping above. Subline states append-only semantics (copy above).
- `trigger_source` rendered as a house `StatusChip`-style chip next to the run id (manual = neutral/blue, deploy = muted).

### D. Webhook simulate card (ACTN-01) — right rail

- App `Select` + payload-shape `Select` — one option per real ingest event kind the ingest seam accepts (enumerate from `ingest.HandleEvent` at implementation; each option label is the event name, description one line in the option's supporting text). No free-form payload editor this phase; no secret fields ever — HMAC signing and secret resolution are server-side only (secrets never reach the browser).
- **Simulate webhook** button — single click, no arm-confirm (non-destructive debug control); disabled with the paused/budget error-state copy when blocked.
- Result block (request/response, no polling): ingest-outcome line per the copy contract; on acceptance a "open run #{id}" link to Run Detail. Outcome vocabulary mirrors the ingest seam's real outcomes (accepted / rejected / duplicate).

## States & Interactions

| State | Contract |
|-------|----------|
| Loading (first paint) | `Skeleton` for KPI cards; `LoadingState` for feed and rails; panel selects show a "Loading…" option until versions resolve |
| Empty | Copy-table rows above; feed empty state keeps the trigger CTA reachable |
| Error / stale | `usePolling` retains last payload; inline warning `Alert` names the surface; never a blank swap |
| Live updates | Feed rows animate in (slide-in, primary-soft flash); KPI numbers swap without layout shift; LIVE chips pulse while a run is in flight |
| Populated | Sketch 001-A anatomy verbatim |
| Partial | Feed rows without evidence render no thumbs (row stays expandable when a detail exists); KPI deltas render "—" when no prior-day baseline |
| Blocked | Pause/budget/zero-approved states disable step 2 with exact error copy — never silently queued |
| Overflow / long text | Plan names ellipsis with `min-width: 0`; mono fields fixed-grid columns; pause reason and trigger reason clamp to their inputs (backstop below) |
| Zero / one / many | Plan versions: 0 → escape hatch, 1 → preselected, many → Select; apps: chips render one row per registered app |
| Reduced motion | `@media (prefers-reduced-motion: reduce)` disables the feed slide-in, LIVE pulse, and busy-dot pulse; status remains text-labeled (motion is never the sole signal) |

## i18n & Accessibility

- Every string above is an `e2ai` translation key; no hardcoded English in JSX (house `useI18n('e2ai')` pattern). Four locales ship with the manifest (`en-US`, `pt-BR`, `es`, `ro`).
- Feed rows are buttons with `aria-expanded`; detail strips are labelled regions; the live feed announces via one `aria-live="polite"` region (row count / latest event), not per-row announcements.
- Paused banner and budget strip are announced on change; pause confirm requires the reason input (validated, `aria-describedby`).
- Focus rings use the house focus ring token (primary); chips and dots always pair color with text labels (PASS/FAIL/LIVE…).
- Desktop-first admin module — no 44px touch-target requirement (house convention); minimum hit area 24px on chips/buttons via padding.
