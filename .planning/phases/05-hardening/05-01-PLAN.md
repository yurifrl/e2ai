## Wave 1 — foundation (parallel, disjoint files)

**T1 — Go data + API foundation** (`P5GoFoundation`)
- Migration `0007_hardening.sql`: `test_quarantine` table (app_id, test identity file+title, reason, evidence artifact ref, status active|lifted, quarantined_by [agent|human], created_at, expires_at); `registered_apps` additions (edge_sweep_enabled bool default false, edge_sweep_interval_minutes int, edge_sweep_step_ceiling int, flake_alert_threshold numeric); `runs.trigger_source` gains `sweep` (check 0001 constraint first). Append new tables to `appTables` drop list.
- `api/internal/flakes/`: cross-run flake-rate queries (test identity = (file,title), per-app windows); quarantine store with guarded mutations (activate/lift/expire) + HTTP Mount (queue pattern from agents/http.go: Mount/auth/error mapping); evidence-gated retry policy hook in verdict/report path — retry classification only for infra-class, never APP_BUG.
- `api/internal/trends/`: aggregation queries — verdict-flip rate (same suite, ≥5-run window, per app), per-run agent cost (aggregate agent_sessions + session_steps), pass/fail history; HTTP Mount.
- Agent-facing corpus read endpoint (runner-token gated, agents/http.go) so Vision Judge can fetch expected behaviors: list/get by app+key.
- APPS-03 Go: honor `webhook_secret_ref` per app in ingest (render from vault ref when set; fall back to shared WEBHOOK_SECRET when NULL); unknown-app webhook event → quarantine-ish event row for admin triage, not a crash.
- Owns all main.go wiring for the above mounts.

**T2 — Roster completion, TS** (`P5Roster`)
- `agentnavigator.ts`: a11y-tree-grounded locator-first loop over SurfaceDriver (web/android/ios) — plan steps → locator resolution → act; Stagehand act() NL fallback (dep already declared); log pre-action a11y snapshot + resolved locator in step evidence; vision verify at decision points only, never click blind.
- `agentjudge.ts`: independent session loop — fetch expected behaviors from the agent corpus endpoint, gather run evidence, structured JSON verdict schema (parsed-field comparison, no-citation → INCONCLUSIVE, 2-of-3 rerun for contested verdicts before AGENT_ERROR filing), deterministic side-effect assertions alongside VLM judgment ("LLM narrates; code asserts").
- Role entries wired in `index.ts` for navigator, vision_judge, edge_hunter, flake_analyst (last two: bounded loop consumers with role prompts; edge_hunter sweep driver lands T3), per-role system prompts as versioned config, budgets respected via existing budget.ts + step ceilings.
- Refuse-to-heal gate in navigator repair suggestions: below confidence floor → escalate (learning append), never silently rewrite; error-state pages never healed.
- Owns agentrunner/src only. No Go files, no package.json changes.

**T3 — Agentic trajectory reports, Go** (`P5Trajectory`)
- report/package: for agentic runs, load agent_sessions + session_steps into report DTOs — trajectory filmstrip extension (kind, decision, action, evidence artifact refs, tokens, cost) mirroring the locked page.go ↔ types.ts contract; only additive DTO fields (no renames).
- REPT-04 completion on the Go side; web consumption lands T6.
- Owns api/internal/report/ only.

## Wave 2 — consumers (after T1)

**T4 — Edge sweeps + Flake Analyst** (`P5EdgeSweeps`)
- Periodic River job (default queue, DB-driven per-app opt-in from 0007 columns): creates sweep runs (trigger_source `sweep`) + enqueues edge_hunter sessions with the app's step ceiling; findings append corpus learnings (human-promote only).
- Flake Analyst trigger: when flake rate crosses the app's alert threshold, enqueue a flake_analyst session that reads flake-rate API and proposes quarantine candidates (quarantine activation stays admin-gated HTTP; agent proposes via learning/quarantine-proposal records, humans confirm).
- Alerting: flake-rate and flip-rate thresholds produce alert events surfaced by the trends API (log line + admin-visible flag; no external notifications in v1).

**T5 — MCP read-only surface** (`P5Mcp`)
- `api/internal/mcp/`: MCP Streamable-HTTP (JSON-RPC) endpoint, read-only tools: `list_runs` (filters app/status/verdict/window), `get_run` (detail + verdict + classification reason), `get_failure_evidence` (per-test evidence + token-gated artifact links), `get_flake_rates`, `get_quarantine`. Reuse runs/flakes/trends queries; Mount pattern from agents/http.go; service-token auth; every response cites run id + machine-checkable evidence links.
- No mutation tools. REPT-02 confirmed here: classification reason field is mandatory in get_run output (delivered — verify, checkbox).

**T6 — Admin web pages** (`P5Web`)
- Trajectory view on RunReportPage (consumes T3 DTOs).
- TrendsPage (flip rate, history, cost per run/agent), QuarantinePage (queue + activate/lift actions, approvals-queue pattern), CorpusHealthPage (stale/flaky/verified rollups + promotion queue link).
- Manifest nav sections + commands + 4 locale files each; lib/types.ts mirrors new DTOs exactly.

## Success criteria (goal-backward)

- Every failure report answers one question: app bug / expectation gap / agent flake / infra — machine-assigned class + plain-language reason (REPT-02 verified end to end).
- Agentic run report carries full trajectory + per-step evidence citations; missing citation renders INCONCLUSIVE, never PASS (REPT-04).
- Flake rates computed per test per app from real run history; quarantine activate/lift works end to end with admin UI; APP_BUG never auto-retried (FLAK-01).
- Selector-repair proposals never mutate without human approval; below-floor and error-page cases escalate (FLAK-02).
- Trends page shows verdict-flip rate (empirical ≥5-run window), run history, cost per run/agent (TREN-01).
- Coding agent can query runs/failures/evidence via MCP read-only tools (MCP-01).
- Edge Hunter runs scheduled bounded sweeps on opt-in apps only; findings are learnings, never auto-promoted (EDGE-01).
- Second app onboarding = registry yaml + config, zero code (APPS-03).
- Navigator: locator-first with a11y evidence; Stagehand only as fallback; vision verifies (AGNT-03). Judge: independent session, gateway role routing, corpus oracle, structured verdicts (AGNT-04). Roster handoffs through DB only (AGNT-01).
