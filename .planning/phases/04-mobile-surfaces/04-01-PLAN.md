## Wave 2 — mobile drivers (TS) || readiness (TS)

### T5: Android driver (Maestro + adb)
- **Files:** `agentrunner/src/surface-android.ts` (+tests), `local/android/` (device config: AVD name, boot probe), `local/MOBILE-TOOLING.md` (boot command record).
- **Steps:** boot: launch AVD → poll `adb shell getprop sys.boot_completed` (readiness probe, never sleep); cold-boot failure/adb disconnect → step failure classified `INFRA_FLAKE` (typed error carrying boot log path). Driving: Maestro CLI invocation of YAML flows (`maestro test <flow.yaml>`), generated per plan step; capture: Maestro screenshot/video (fast path), `adb screencap` one-offs only. Serialize: driver refuses to boot if another emulator instance is up (single-device rule). Teardown always: `adb emu kill` on session end.
- **Acceptance:** unit tests with fake adb/maestro binaries (boot-ready path, boot-timeout → INFRA_FLAKE, disconnect → INFRA_FLAKE, teardown called); driver never shells to a device when serialized-lock fails.
- **Reqs:** PLAT-02, PLAT-04 (classification half).

### T6: iOS driver (simctl + Maestro + idb-optional)
- **Files:** `agentrunner/src/surface-ios.ts` (+tests), `local/ios/` (device/UDID config).
- **Steps:** lifecycle: `xcrun simctl boot` → poll `simctl bootstatus` (readiness probe); install via `simctl install`; erase per session if configured. Input: Maestro flows (same YAML driving layer as Android — one driving model, two lifecycle adapters). Grounding: a11y tree via Maestro's accessibility driving; idb optional (guarded binary check — absent → skip gracefully, never WDA). Capture: `simctl io screenshot`/`io recordVideo`. Boot/screenshot failure → INFRA_FLAKE with log attached. Never WDA tap paths (RESEARCH §1).
- **Acceptance:** unit tests with fake simctl/maestro binaries (boot-ready, boot-timeout → INFRA_FLAKE, idb-absent graceful, teardown); no WDA strings anywhere.
- **Reqs:** PLAT-03, PLAT-04 (classification half).

### T7: WebView readiness probes + INFRA_FLAKE plumbing (TS)
- **Files:** `agentrunner/src/{readiness.ts,surface-web.ts,surface-android.ts,surface-ios.ts}` (+tests), `agentrunner/src/loop.ts` (probe insertion point).
- **Steps:** `readiness.ts`: animation-settle + network-idle + render-idle probes; render-idle = two consecutive stable frames (fallback when no debug bridge), network-idle from available signals (CDP on web driver, Maestro/adb on mobile); probe result recorded as step evidence. Double-lag: capture only after readiness, re-check stability after capture. INFRA_FLAKE plumbing: typed failure class flows from drivers → step append → run classification; `verdict`/`derive` (Go) treats infra-class failures distinctly from APP_BUG (read failure class from step/note field — add if a column is needed, same migration cadence as T4).
- **Acceptance:** unit tests: unstable-frame → no capture until stable; boot-flake classified INFRA_FLAKE end-to-end (fake driver → step → derive); web driver probes don't slow the happy path beyond budget.
- **Reqs:** PLAT-04.

## Verification approach

- Per task commit: Go (`go build ./... && go test <pkgs> -count=1`), TS (`tsc --noEmit && npm test`).
- Drivers are unit-tested against fake binaries (boot probes, timeouts, teardown); the ONLY real-device proof is T9's live smoke — no emulator/simulator in the unit suite, ever (serialized-device rule + CI determinism).
- Cross-task contracts locked here: env contract (T1 producer, all TS consumers); `E2AI_SURFACE` (T4 producer, T3/T5/T6 consumers); INFRA_FLAKE typed failure (T5/T6 producers, T7 plumbing, T9 e2e proof); per-run image (T8 producer/consumer, T9 gate).

## Threat model deltas (SAFE-01 carryover)

- Mobile drivers spawn device tooling (adb/maestro/simctl): same egress allowlist discipline; device tooling may talk only to localhost device ports + staged origins (allowlist extension in T3).
- Emulator/simulator binaries never receive app credentials; boot logs attached to INFRA_FLAKE evidence are scanned by the existing credential fence before serving.
- No new external egress: staging domains + aihub + api, unchanged.

## Success criteria (goal-backward)

- An approved plan targeting `ios`/`android` surfaces spawns a session whose driver boots the device, drives it via Maestro flows, and captures readiness-gated evidence — on this Mac.
- Emulator cold-boot failure lands as `INFRA_FLAKE` with boot log attached, never `FAIL`.
- Screenshot happens only after animation/network/render-idle probes pass (double-lag guarded).
- A runner-image upgrade can be canaried on one run; stored version-vs-pin drift is queryable.
- Device use is serialized — two concurrent sessions cannot double-boot a device.
